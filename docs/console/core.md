# OpenCode Console Core 包详解

## 概述

`@opencode-ai/console-core` 是 OpenCode 项目控制台的核心业务逻辑层包，版本号为 1.1.45。该包作为私有包，提供完整的数据库访问层、业务逻辑实现、认证授权系统、计费管理等功能，是整个 OpenCode 平台数据管理和业务规则的核心引擎。包的设计采用模块化架构，通过 Drizzle ORM 与 MySQL 数据库交互，使用 Zod 实现运行时类型验证，结合 AsyncLocalStorage 实现请求上下文的隔离管理。

控制台核心包承担着平台最关键的业务职责，包括用户身份认证与授权、工作区管理、API 密钥管理、模型与提供商管理、计费与订阅管理等核心功能。通过 Actor 模式的实现，系统能够精确追踪每个请求的操作者身份及其权限范围；通过 Context 的设计，实现了请求级别的数据隔离；通过完善的事务支持，确保了数据操作的原子性和一致性。

## 核心架构设计

### Actor 授权模式

Actor 系统是控制台核心包权限管理的核心，通过类型化的操作者定义实现精确的访问控制。该模式将每个请求的发起者抽象为不同类型的 Actor，每种类型拥有不同的属性集和权限范围。系统定义了四种 Actor 类型：Account 类型代表账户级别操作，拥有账户 ID 和邮箱信息；User 类型代表用户级别操作，包含用户 ID、工作区 ID、账户 ID 和角色信息；System 类型代表系统级操作，仅包含工作区 ID；Public 类型代表公开访问，不携带任何属性信息。

Actor 系统的实现基于 Context 模块提供的 AsyncLocalStorage 能力，确保每个请求都能安全地访问当前操作者的信息。通过 `Actor.use()` 方法，业务代码可以随时获取当前操作者的上下文；通过 `Actor.provide()` 方法，系统可以在请求入口处设置操作者信息；通过 `Actor.assert()` 方法，代码可以验证当前操作者是否符合预期类型；通过 `Actor.assertAdmin()` 方法，系统可以确保只有管理员角色才能执行特定操作。

Actor 系统还提供了便捷的辅助函数：`Actor.userID()` 返回当前用户的 ID；`Actor.workspaceID()` 返回当前工作区的 ID；`Actor.userRole()` 返回当前用户的角色（admin 或 member）。这些函数简化了业务代码中频繁的属性访问，同时保持了代码的类型安全性。

### 请求上下文管理

Context 模块采用 AsyncLocalStorage 实现请求级别的数据隔离，这是 Node.js 环境下实现无侵入式上下文管理的标准方案。Context.create() 函数创建一个新的上下文存储实例，提供 `use()` 方法获取当前上下文值，`provide()` 方法在回调中临时设置上下文值。如果在上下文外调用 `use()` 方法，系统会抛出 NotFound 错误，帮助开发者快速定位上下文缺失的问题。

Context 模块的设计遵循依赖倒置原则，不依赖于任何具体的业务类型。通过泛型参数 T，Context 可以存储任何类型的数据，目前主要用于存储 Actor 信息。这种设计使得 Context 模块具有良好的复用性，可以应用于日志上下文、数据库事务上下文、用户会话上下文等多种场景。

### Zod 函数包装器

fn 模块提供了一个轻量级的函数包装器，将 Zod Schema 验证与业务函数结合，实现输入参数的类型安全和自动验证。包装后的函数保留了两个调用入口：普通入口会自动验证输入参数并抛出验证错误；force 入口则跳过验证直接执行，适用于性能敏感或已确保证据有效的场景。

fn 模块的设计理念是让业务代码专注于逻辑实现，而非重复的参数验证代码。每个使用 fn 包装的函数都自动获得 schema 属性，方便外部代码访问其参数规范。业务模块中的几乎所有函数都使用 fn 包装，确保了系统边界的健壮性。

### 数据库连接管理

Database 模块封装了 Drizzle ORM 的数据库连接和事务管理。Database.use() 方法接收一个回调函数，在数据库事务中执行该函数并返回结果。事务内的所有数据库操作要么全部成功，要么全部回滚，确保了数据的一致性。模块还支持读写分离的查询优化，业务代码可以根据查询性质选择合适的访问方式。

数据库连接的配置通过 drizzle.config.ts 文件管理，支持开发环境和生产环境使用不同的数据库实例。SST 框架的集成使得数据库连接能够根据部署环境自动配置，无需手动管理连接字符串和凭据。

## 数据库架构设计

### 核心表结构

**AccountTable（账户表）**：
账户是 OpenCode 平台的最高级别实体，用于聚合用户身份和认证信息。每个账户拥有独立的标识符和创建时间戳，支持软删除机制。账户与用户之间是一对多关系，一个账户可以包含多个用户成员。账户的核心作用是实现跨工作区的身份统一，用户使用同一套认证信息可以访问其所属的所有工作区。

**UserTable（用户表）**：
用户是工作区内的成员实体，通过账户 ID 关联到账户，通过工作区 ID 关联到工作区。用户表包含丰富的属性：邮箱地址用于身份识别，显示名称用于界面展示，角色定义（admin 或 member）控制权限范围，月度限制控制 API 调用配额，月度使用量追踪当前计费周期的资源消耗。表上建立了多个索引以优化查询性能：工作区+账户的唯一索引确保用户在工作区内的唯一性，工作区+邮箱的唯一索引支持邮箱查找，账户和邮箱的全局索引支持跨工作区的身份查询。

**WorkspaceTable（工作区表）**：
工作区是 OpenCode 平台的组织单元，用于隔离不同团队或项目的资源和数据。工作区拥有独立的标识符、URL 友好的 slug 和显示名称。slug 字段用于 API 路由和 URL 展示，需要保持全局唯一性。工作区表是整个数据模型的核心枢纽，用户、密钥、模型、计费等表都通过工作区 ID 与之关联。

**KeyTable（密钥表）**：
API 密钥用于程序化访问 OpenCode 服务，每个密钥归属于特定工作区的特定用户。密钥采用 "sk-" 前缀加上 64 位随机字符的格式，符合行业最佳实践。密钥表记录密钥名称、密钥值、最后使用时间等属性，支持软删除机制确保审计追溯。密钥列表查询会根据当前用户的角色返回不同粒度的信息：管理员可以看到所有密钥的概要，普通用户只能看到自己的完整密钥值。

**ProviderTable（提供商表）**：
提供商用于存储第三方 AI 服务的 API 密钥，支持 BYOK（Bring Your Own Key）模式。工作区管理员可以配置多个 AI 服务提供商，系统会根据模型配置路由请求到对应的提供商。提供商表存储提供商类型（如 OpenAI、Anthropic、Google）和加密的凭据信息，支持软删除以保留历史配置。

**ModelTable（模型表）**：
模型表定义工作区可用的 AI 模型配置，包含模型名称、成本信息、速率限制、试用配置等属性。模型支持多提供商配置，通过权重实现负载均衡，支持故障转移的备用提供商设置。模型的成本信息支持多种计费维度：输入 token 费用、输出 token 费用、缓存读取费用、不同窗口期的缓存写入费用。模型表还支持匿名访问配置、BYOK 提供商指定、粘性提供商策略等高级特性。

**BillingTable（计费表）**：
计费表存储工作区的支付相关信息，包括 Stripe 客户 ID、支付方式 ID、余额、充值配置等。系统支持自动充值功能，当余额低于阈值时自动发起充值请求。充值金额、触发阈值等参数可配置，最小充值金额为 10 美元，默认充值金额为 20 美元。计费表还记录订阅状态和套餐信息，与 SubscriptionTable 关联实现完整的订阅生命周期管理。

**SubscriptionTable（订阅表）**：
订阅表管理工作区的订阅计划，存储订阅的 Stripe 订阅 ID、状态、当前期间等信息。订阅支持多种套餐，包括 Black 200、Black 100、Black 20 等不同级别，每个级别有不同的功能限制和使用配额。订阅状态包括活跃、取消、Past Due（逾期）等，状态变化会触发相应的工作流处理。

**UsageTable（使用量表）**：
使用量表记录 API 调用的详细计费信息，包括调用时间、工作区 ID、模型 ID、输入输出 token 数量、费用金额等字段。表设计支持高吞吐的写入和按时间范围查询，配合 BillingTable 的月度汇总实现精确的计费核算。

**PaymentTable（支付表）**：
支付表记录工作区的充值和扣款流水，包括支付时间、金额、Stripe 支付意图 ID、状态等信息。支付表支持与 Stripe Webhook 集成，自动同步支付状态变化。支付历史用于财务对账和用户查询，查询接口默认返回最近 100 条记录。

**AuthTable（认证表）**：
认证表存储用户的认证凭据和提供商信息，支持多种认证方式的灵活配置。当前实现主要使用邮箱认证，AuthTable 记录 provider（认证类型）和 subject（凭据标识）到 account ID 的映射。AuthTable 与 UserTable 通过 account ID 关联，实现用户身份到账户的关联。

**IpTable（IP 表）**：
IP 表记录工作区的 IP 白名单配置，用于企业版的安全访问控制。管理员可以配置允许访问 API 的 IP 地址范围，未经授权的 IP 访问将被拒绝。IP 表支持软删除机制，配置变更保留审计历史。

**BenchmarkTable（基准测试表）**：
基准测试表记录 AI 模型的性能基准数据，用于评估和比较不同模型的响应速度和质量分数。基准测试支持多种评估维度和测试场景，为模型选择和优化提供数据支撑。

### 共享类型定义

**timestamps（时间戳）**：
所有业务表都继承统一的时间戳定义，包含 timeCreated（创建时间）、timeUpdated（更新时间）、timeDeleted（删除时间）三个字段。创建和更新字段默认自动填充，删除时间字段用于实现软删除逻辑。毫秒级精度（fsp: 3）确保了时间戳的精确性，满足审计和计费场景的需求。

**workspaceColumns（工作区列）**：
所有关联到工作区的表都使用 workspaceColumns 定义的列规范，包含 id（记录 ID）和 workspaceID（工作区 ID）两个字段。workspaceColumns 遵循 DRY 原则，避免在多个表中重复定义相同的列结构。

**ulid（标识符类型）**：
所有主键和外键都使用 ULID（Universally Unique Lexicographically Sortable ID）格式，固定长度为 30 个字符。ULID 相比 UUID 具有更好的时间排序性和可读性，同时保持了足够的唯一性保证。ulid 类型工厂函数创建符合规范的 varchar 列。

**utc（UTC 时间）**：
所有时间相关字段都使用 UTC 时区存储，确保跨时区数据的一致性。应用层根据需要转换为本地时区展示，存储层始终使用 UTC 避免时区混淆。时间精度设置为毫秒级，满足大多数业务场景的需求。

## 业务逻辑模块

### Actor 模块详解

Actor 模块实现了 OpenCode 平台的授权核心，采用类型安全的 Actor 模式管理操作者身份。模块定义了四种 Actor 类型，每种类型服务于不同的授权场景：Account Actor 用于账户级别的管理操作，如跨工作区的账户查询；User Actor 是最常用的类型，代表工作区内的具体用户，包含完整的身份和权限信息；System Actor 用于系统内部触发的操作，如定时任务和 Webhook 处理器；Public Actor 用于公开访问场景，如健康检查和公开 API。

Actor 的使用遵循明确的模式：首先通过 Actor.provide() 在请求入口设置当前操作者信息，然后通过 Actor.use() 在业务代码中获取操作者上下文，通过 Actor.assert() 验证操作者类型是否符合预期，通过 Actor.assertAdmin() 确保只有管理员可以执行敏感操作。这种模式将授权检查与业务逻辑分离，使代码更加清晰和可维护。

Actor 模块与日志系统集成，每个 Actor 的创建和提供都会生成结构化的日志记录。日志包含 Actor 类型和关键属性，便于问题排查和安全审计。Log.provide() 的嵌套调用确保了日志上下文的正确传递，即使在复杂的异步操作中也能追踪完整的调用链。

### Black 订阅模块

Black 模块实现了 Black 订阅计划的业务逻辑，包括配额管理、套餐转换、使用量追踪等功能。Black 模块定义了三个订阅级别：plan200（高级套餐）提供最高的固定和滚动配额；plan100（标准套餐）提供中等配额；plan20（基础套餐）提供入门级配额。各套餐的配额限制存储在外部配置资源（Resource.ZEN_BLACK_LIMITS）中，支持运行时配置更新而无需重新部署。

BlackData 命名空间封装了配额数据的验证和查询逻辑。validate() 函数使用 Zod Schema 验证配置数据的格式正确性；getLimits() 函数根据订阅计划返回对应的配额限制；planToPriceID() 和 priceIDToPlan() 函数实现套餐与 Stripe 价格 ID 的双向映射，支持订阅创建和状态同步。

Black 命名空间提供了使用量分析的核心功能。analyzeRollingUsage() 函数计算当前使用量是否超过滚动窗口配额，返回配额状态（ok、limited）和重置时间；analyzeFixedUsage() 函数计算月度固定配额的使用状态，支持配额耗尽后的自动处理逻辑。这些分析函数被 Billing 模块调用，在 API 调用前执行配额检查。

### Billing 计费模块

Billing 模块实现了完整的计费业务逻辑，包括余额管理、支付处理、订阅管理、费用计算等功能。Billing 模块集成了 Stripe SDK，提供支付处理、订阅创建、退款处理等能力。stripe() 工厂函数创建配置好的 Stripe 客户端，使用 Fetch HTTP 客户端确保与 Bun 运行时的兼容性。

Billing 模块的核心功能包括：get() 获取当前工作区的计费信息；payments() 查询支付历史；usages() 查询使用量记录；reload() 执行余额充值；createSubscription() 创建新订阅；cancelSubscription() 取消订阅。充值逻辑支持自动充值模式：当余额低于 RELOAD_TRIGGER（5 美元）时触发自动充值，充值金额为 RELOAD_AMOUNT（20 美元），最小充值金额为 RELOAD_AMOUNT_MIN（10 美元）。

费用计算是 Billing 模块的重要功能之一。calculateFeeInCents() 函数计算 Stripe 交易费用，算法基于 Stripe 标准费率（2.9% + 0.30 美元）反推用户需要支付的总额。计算结果用于向用户展示真实费用和预估余额变化。

### User 用户模块

User 模块实现了用户管理的完整业务逻辑，包括用户列表查询、单用户获取、邀请用户、更新用户、删除用户等功能。模块使用 Zod Schema 定义输入验证规则，确保 API 边界的数据合法性。

list() 函数返回当前工作区的所有用户列表，包含用户的完整信息和关联的认证邮箱。查询使用 LEFT JOIN 连接 UserTable 和 AuthTable，支持已删除用户的过滤。fromID() 函数根据用户 ID 查询单个用户的详细信息，用于用户详情页面和权限检查。

invite() 函数实现用户邀请功能，邀请新用户加入工作区。邀请流程检查邀请者的管理员权限，验证被邀请邮箱是否已存在账户，创建用户记录并返回结果。邀请可以指定用户的角色（admin 或 member）和月度使用限额。

update() 和 remove() 函数分别实现用户信息的更新和软删除。更新支持修改名称、角色、月度限额等字段；删除操作仅设置 timeDeleted 时间戳，保留数据记录供审计追溯。敏感操作如修改角色、删除用户都经过管理员权限检查。

### Model 模型模块

Model 模块实现了 AI 模型配置的管理功能，包括模型列表查询、模型详情获取等。ZenData 命名空间封装了模型定义的验证和加载逻辑，支持从外部配置资源动态加载模型定义。

Model 模块支持多种模型配置：基础配置包括模型名称、输入输出成本；高级配置包括缓存成本（5 分钟和 1 小时窗口）、200K token 成本、BYOK 提供商配置、粘性提供商策略；试用配置包括试用提供商和试用限额；提供商配置支持多提供商路由、权重分配、故障转移等。

list() 函数从外部配置资源加载模型定义和提供商配置，支持分片配置（ZEN_MODELS1 到 ZEN_MODELS8）的大规模配置存储。配置加载后进行 Zod Schema 验证，确保配置格式的正确性。模型配置支持 AllowAnonymous 标志，允许未登录用户的有限使用。

### Provider 提供商模块

Provider 模块实现了 AI 服务提供商的管理功能，包括提供商列表查询、创建新提供商、删除提供商等操作。提供商配置支持 BYOK 模式，允许工作区管理员配置自己的 API 密钥。

create() 函数支持插入新提供商或更新现有提供商的配置，使用 ON DUPLICATE KEY UPDATE 语法实现 upsert 语义。删除操作执行软删除，设置 timeDeleted 时间戳保留历史记录。提供商的操作需要管理员权限，普通用户只能查看提供商列表。

### Key 密钥模块

Key 模块实现了 API 密钥的完整生命周期管理，包括密钥列表查询、创建密钥、删除密钥、更新密钥等功能。密钥是用户程序化访问 OpenCode 服务的主要方式，密钥安全是平台安全的重要组成部分。

list() 函数返回当前工作区的密钥列表，根据调用者的角色返回不同粒度的信息：管理员可以看到所有密钥的概要，但只能看到自己密钥的完整值；普通用户只能看到自己创建的密钥。这种设计保护了其他用户的密钥隐私，同时满足管理需求。

create() 函数生成符合安全标准的 API 密钥：前缀为 "sk-" 标识密钥类型，后面跟随 64 位随机字符（大小写字母和数字）。密钥生成使用 crypto.getRandomValues() 获取密码学安全的随机数，确保密钥的不可预测性。密钥创建时会分配唯一的 keyID，便于后续的管理操作。

remove() 函数执行密钥的软删除，设置 timeDeleted 时间戳。删除操作检查调用者权限，普通用户只能删除自己的密钥，管理员可以删除任何密钥。敏感操作记录完整的审计日志。

### Provider 提供商模块

Provider 模块实现 AI 服务提供商的管理功能，支持工作区配置自定义的 API 凭据。提供商用于支持 BYOK（Bring Your Own Key）模式，允许用户使用自己的 API 密钥调用 AI 服务。

Provider 模块的设计考虑了多提供商场景：一个模型可以配置多个提供商，系统根据权重和可用性自动选择提供商。提供商支持禁用状态，可以临时下线某个提供商而不删除其配置。提供商配置使用加密存储，防止凭据泄露。

## 工具函数模块

### fn 函数包装器

fn 模块提供轻量级的函数包装，将 Zod Schema 验证与业务逻辑解耦。包装后的函数自动验证输入参数，验证失败时抛出包含详细错误的异常。fn 模块的设计理念是让业务代码专注于逻辑实现，参数验证作为横切关注点统一处理。

fn 模块返回的函数具有两个调用入口：普通入口强制执行验证，适用于外部 API 和不可信输入源；force 入口跳过验证直接执行业务逻辑，适用于已验证场景或性能敏感路径。两个入口共享同一个 schema 属性，便于外部代码进行类型推断和参数验证。

fn 模块的实现利用了 Zod 的强大验证能力：支持所有 Zod 类型，包括基本类型、对象、数组、联合、Optional、Nullable 等；支持自定义验证器和转换器；支持嵌套对象和递归类型；生成精确的错误信息指出具体字段问题。

### Date 日期工具

Date 模块提供日期处理的标准化函数，核心函数 getWeekBounds() 计算给定日期所在周的范围（周一至周日）。函数实现考虑了时区问题，使用 UTC 时间计算确保跨时区的一致性。周边界计算用于使用量统计和配额重置等周期性逻辑。

getWeekBounds() 返回包含 start（周一开始）和 end（下周一）的对象，精度为毫秒级。计算算法首先确定给定日期是周几，然后计算到周一的天数偏移，最后调整时间部分为 0:0:0:0。这种实现确保了无论给定日期在什么时候，计算出的周边界都是准确的。

### Price 价格工具

Price 模块提供价格计算的工具函数，核心函数 centsToMicroCents() 将美分数转换为微美分数。OpenCode 内部使用微美分（百万分之一美分）作为金额精度，避免浮点数运算的精度问题。Stripe 等外部服务也使用类似的整数分表示法。

价格计算采用整数运算避免精度损失：输入金额（美元）乘以 100 转换为美分数，再乘以 1000000 转换为微美数。计算结果的逆运算同样使用整数除法，确保四舍五入行为的一致性。

### Log 日志工具

Log 模块提供结构化日志记录能力，Log.create() 创建日志记录器实例，支持标签配置用于日志分类和过滤。日志输出包含时间戳、日志级别、标签、消息、上下文数据等字段，支持 JSON 格式便于日志聚合和分析。

Log.provide() 函数在回调中临时设置日志上下文，上下文数据会自动附加到回调中所有日志记录的字段中。这种模式与 Actor 模块和 Context 模块配合，确保异步调用链中的日志能够追溯完整的上下文信息。

### Memo 记忆化工具

Memo 模块提供函数结果的记忆化缓存能力，避免重复的昂贵计算。记忆化基于输入参数的唯一标识进行缓存键生成，支持配置缓存有效期和最大缓存条目数。Memo 模块适用于计算密集型函数，如配置解析、模型成本计算等。

### 环境变量工具

env.cloudflare 模块封装 Cloudflare 环境变量的访问，提供类型化的环境变量读取接口。环境变量使用 Resource 模式管理，支持默认值和必填检查。环境变量的变更不需要重新部署即可生效，支持动态配置更新。

## 数据库迁移系统

### 迁移文件命名规范

OpenCode 控制台核心包采用 Drizzle ORM 的迁移管理系统，迁移文件遵循严格的命名规范。每条迁移文件包含一个序号前缀（0000 到 0055）和一个描述性名称，描述性名称采用「形容词_角色名称」的格式，如 "fluffy_raza"、"serious_whistler" 等。这种命名方式便于追踪迁移历史和理解迁移目的。

迁移系统包含两种文件格式：SQL 迁移文件（.sql）包含直接的数据库操作语句，执行速度快但缺乏回滚能力；JSON 快照文件（_snapshot.json）记录迁移后的数据库结构快照，用于迁移生成和版本比对。Drizzle Kit 工具使用这些文件管理数据库结构的版本控制。

### 迁移元数据管理

meta 目录下的_snapshot.json 文件记录每个版本的数据库结构快照，包含所有表的定义、索引、约束等信息。快照文件由 Drizzle Kit 自动生成，确保与实际迁移的一致性。这些快照文件也是数据库文档的重要来源，可以从中了解数据库的完整结构。

_journal.json 文件是迁移日志，记录已执行的迁移序列和执行状态。Journal 文件用于 Drizzle Kit 判断哪些迁移已执行、哪些待执行，实现增量迁移。Journal 文件的格式包含迁移名称、执行时间、执行状态等信息。

### 迁移执行流程

迁移执行通过 drizzle-kit 工具管理，支持 up（应用迁移）和 down（回滚迁移）操作。开发环境使用 `bun run db-dev` 命令，指定 dev stage 应用开发环境的迁移；生产环境使用 `bun run db-prod` 命令，指定 production stage 应用生产环境的迁移。

SST 框架集成使得迁移可以根据部署环境自动选择目标数据库。环境变量和配置文件定义各环境的数据库连接参数，迁移执行时自动加载对应环境的配置。这种设计确保了开发、测试、生产环境的数据库结构管理的一致性。

## 运维脚本系统

black-onboard-waitlist.ts 脚本处理候补用户的 Black 订阅开通。候补用户列表从外部配置加载，脚本批量处理用户的订阅创建和配额设置。脚本支持部分成功和部分失败的容错处理。

black-transfer.ts 脚本实现 Black 订阅在不同工作区之间的转移。转移需要验证源工作区的权限和目标工作区的状态，确保转移过程的安全性和数据完整性。

black-cancel-waitlist.ts 脚本处理候补用户队列的取消操作，从队列中移除指定用户或全部清空。取消操作的执行需要候补用户的管理权限。

credit-workspace.ts 脚本为工作区添加或扣减积分，支持批量处理和备注记录。积分操作生成相应的账务记录，用于财务对账和用户查询。脚本验证积分余额的充足性，防止透支操作。

lookup-user.ts 脚本提供用户信息的快速查询功能，支持按邮箱、账户 ID、工作区等多种条件查询。脚本输出用户的详细信息，包括关联的工作区、角色、认证信息等。

pull-models.ts 脚本从外部配置源拉取最新的模型定义，更新数据库中的模型配置。模型配置支持热更新，无需重新部署即可生效。脚本处理配置合并和冲突解决，确保更新的正确性。

promote-models.ts 脚本实现模型的升级推广流程，将新模型从测试状态提升为正式可用状态。推广过程包括配置验证、功能测试、监控设置等步骤。

update-models.ts 脚本批量更新模型配置，如价格调整、限制变更等。脚本支持从配置文件读取更新内容，实现配置的外部化管理。

### 数据库维护脚本

reset-db.ts 脚本提供数据库的重置功能，用于开发环境的数据库重建或测试数据清理。脚本执行前需要多次确认，防止误操作导致数据丢失。重置操作会清空所有业务数据，保留数据库结构。

## 外部服务集成

### Stripe 支付集成

Billing 模块深度集成 Stripe 支付平台，提供完整的订阅管理、支付处理、退款处理等能力。Stripe 集成使用最新的 API 版本（2025-03-31.basil），确保使用最新的功能和安全特性。HTTP 客户端使用 Fetch 实现，兼容 Bun 运行时环境。

Stripe 集成支持以下主要功能：订阅创建和取消、支付方式管理、余额充值、退款处理、Webhook 事件处理。WebHook 处理支持签名验证，防止伪造事件攻击。事件处理包括支付成功、订阅更新、Invoice 生成等多种类型。

### AWS STS 集成

AWS 模块使用 AWS SDK 集成 AWS STS 服务，支持临时凭据获取和跨账户访问。AWS 集成主要用于生产环境的资源访问控制，支持 IAM 角色和策略的精细配置。

aws4fetch 库提供 Fetch 风格的 AWS 请求封装，简化 AWS API 的调用方式。集成支持 AWS 区域配置、凭据自动刷新、请求签名等标准 AWS 功能。

### Cloudflare 集成

环境变量管理使用 Cloudflare 的 Runtime 机制，支持热更新的配置管理。Resource 模式将环境变量封装为强类型的属性访问，提供默认值和必填检查。配置变更通过 Cloudflare Dashboard 或 API 完成，无需重新部署应用。

## 开发运维指南

### 开发环境配置

开发环境使用 SST 框架的 stage 功能管理不同环境的配置。dev stage 对应开发数据库，production stage 对应生产数据库。数据库连接通过 drizzle.config.ts 配置，支持环境变量的覆盖。

开发环境的数据库迁移使用 `bun run db-dev` 命令，该命令自动加载 dev stage 的配置并执行迁移。Shell 访问使用 `bun run shell-dev` 命令，可以在开发数据库上执行任意 SQL 操作。

### 生产环境部署

生产环境部署遵循 SST 框架的标准流程，通过 `sst deploy --stage production` 命令完成部署。部署过程包括代码构建、配置同步、数据库迁移、资源创建等步骤。生产环境的配置通过环境变量管理，确保敏感信息的安全。

生产环境的数据库迁移使用 `bun run db-prod` 命令，迁移执行前会进行额外的验证检查。生产环境的任何变更都经过代码审查和测试验证，确保变更的安全性。

### 监控和告警

Billing 模块集成了使用量监控功能，当使用量接近配额限制时触发告警。Black 订阅的使用量追踪支持滚动窗口和固定窗口两种模式，满足不同订阅计划的配额策略。

日志输出结构化为 JSON 格式，支持日志聚合和分析平台的集成。关键操作（如密钥创建、用户删除、支付处理）都有完整的审计日志记录，满足合规审计的要求。

## 总结

`@opencode-ai/console-core` 是 OpenCode 平台控制台的核心引擎，提供了完整的业务逻辑层和数据访问层能力。包的设计遵循模块化、类型安全、运行时验证等现代软件开发最佳实践，通过 Actor 模式实现精确的权限控制，通过 Context 模式实现请求级别的数据隔离，通过 Drizzle ORM 实现类型安全的数据库操作。

核心包涵盖的领域包括：用户和工作区的组织管理、API 密钥的安全管理、AI 模型和提供商的多重配置、完整的计费和订阅管理、与 Stripe 和 AWS 等外部服务的深度集成。通过 56 条数据库迁移，系统保持了数据库结构的版本控制和演进能力。

控制台核心包的设计目标是构建一个可靠、安全、可扩展的业务平台基础。模块化的架构使得各功能域可以独立演进和测试，强类型的设计减少了运行时错误，完整的审计日志满足了企业级的合规要求。这些设计决策共同支撑了 OpenCode 平台在大规模商业运营中的稳定表现。
