# OpenCode SDK 包详解

## 概述

`@opencode-ai/sdk` 是 OpenCode 项目的官方 TypeScript SDK，提供类型安全的 API 客户端和嵌入式服务器功能。该 SDK 通过 OpenAPI 规范自动生成代码，支持服务器发送事件（SSE）、会话管理、项目操作等核心功能，当前版本为 1.1.45。

## 核心架构设计

### 双版本支持策略

SDK 采用双版本架构设计，v1 和 v2 版本并存以确保向后兼容性和渐进式迁移。v1 版本位于 `src/gen` 目录，是 SDK 的稳定基础版本；v2 版本位于 `src/v2/gen` 目录，提供增强功能和优化实现。这种设计允许用户在升级 SDK 时逐步迁移，同时保持现有应用的稳定性。

### 代码生成流程

SDK 的核心代码完全基于 OpenAPI 3.1.1 规范自动生成，使用 `@hey-api/openapi-ts` 工具链实现自动化代码生成。生成过程会创建完整的类型定义、客户端实现、序列化器等组件，确保 SDK 与 API 规范保持严格同步。生成的代码包含类型安全的请求参数、响应类型和错误处理，大幅减少手动编码工作量。

### 模块化导出设计

SDK 提供清晰的模块化导出结构，支持多种导入方式以适应不同使用场景。默认导出包含完整的客户端和服务器功能，客户端导出提供独立的 API 访问能力，服务器导出支持独立的嵌入式服务器运行，v2 版本导出则提供增强的 API 访问功能。这种设计使得 SDK 可以在不同环境和使用模式下灵活应用。

## 核心功能模块

### 客户端功能详解

**createOpencodeClient** 函数是创建 API 客户端的主要入口，提供丰富的配置选项和便捷的使用方式。客户端默认使用无超时设置的 fetch 实现，支持自定义 baseUrl、请求头、认证参数等配置。对于需要在特定目录下操作的应用，可以通过 `directory` 参数自动添加对应的请求头，实现目录感知的 API 调用。

客户端的核心功能包括：请求拦截器支持，允许在请求发送前修改参数或添加认证信息；响应拦截器支持，允许统一处理响应或错误；SSE 事件流支持，提供实时事件订阅能力；类型安全的请求参数，所有 API 调用都有完整的 TypeScript 类型检查。

### 服务器功能详解

**createOpencodeServer** 函数提供嵌入式服务器功能，用于本地开发、测试和集成场景。服务器默认配置为 `127.0.0.1:4096`，支持自定义主机名、端口、超时时间和终止信号。内置服务器可以快速启动 OpenCode API 实例，使开发者能够在本地完整测试客户端功能，无需依赖外部服务。

服务器支持配置选项包括：`hostname` 设置监听地址，`port` 指定服务端口，`timeout` 配置请求超时时间，`signal` 支持通过 AbortSignal 终止服务器。这些选项使得嵌入式服务器能够灵活适应各种开发和测试场景需求。

### 统一创建函数

**createOpencode** 函数将客户端和服务器功能整合在一起，提供一站式解决方案。调用此函数会自动创建服务器实例并配置客户端连接到该服务器，返回包含 `client` 和 `server` 的对象。这种设计简化了本地开发和测试流程，开发者无需手动管理服务器生命周期和客户端配置。

## API 功能覆盖

### 全局管理功能

SDK 提供全面的全局管理 API，支持健康检查、事件订阅和配置管理三大核心功能。健康检查接口（`global.health`）返回服务器运行状态和版本信息，是监控系统集成的基础接口。事件订阅接口（`global.event`）通过 Server-Sent Events 提供全局事件流，支持实时接收系统通知和状态变更。配置管理接口支持获取和更新全局配置，允许动态调整系统行为。

### 项目管理功能

项目管理模块提供项目的列出、当前项目切换和项目级操作能力。项目列表接口（`project.list`）返回所有可用项目的完整信息，支持分页和过滤。项目当前状态接口（`project.current`）获取当前激活项目的详细信息。这些接口使得 SDK 能够支持复杂的多项目工作流和项目管理场景。

### 终端会话管理

PTY（伪终端）管理是 SDK 的核心功能之一，提供完整的终端会话生命周期管理。创建接口（`pty.create`）启动新的终端会话并返回会话标识。列表接口（`pty.list`）返回所有活跃会话状态。删除接口（`pty.remove`）终止指定会话并释放资源。更新接口（`pty.update`）修改会话配置。连接接口（`pty.connect`）建立与现有会话的实时交互连接，支持双向数据传输和实时命令执行。

### 会话交互功能

会话系统是 SDK 的高级功能层，提供基于 AI 的会话创建和提示交互能力。创建接口（`session.create`）初始化新的 AI 会话并返回会话 ID。提示接口（`session.prompt`）向会话发送提示消息，支持文件、文本等多种内容类型的输入。状态接口（`session.status`）查询会话的当前执行状态和结果。这些功能使得开发者能够构建复杂的 AI 交互应用和自动化工作流。

### 工具和资源配置

SDK 提供工具管理和资源配置接口，支持查询可用工具列表和资源访问。工具列表接口（`tool.list`）返回系统中所有可用的工具定义和元数据。路径资源接口（`path.get`）提供文件系统的只读访问能力。版本控制系统接口（`vcs.get`）查询代码仓库的版本控制信息。实例管理接口（`instance.dispose`）提供资源的清理和释放能力，确保资源的有效生命周期管理。

## 技术实现深度解析

### 代码生成器配置

构建脚本使用 `@hey-api/openapi-ts` 进行代码生成，配置了多个定制化插件满足项目需求。TypeScript 插件生成标准类型定义文件，支持 IDE 智能提示和编译时类型检查。SDK 插件创建封装的客户端类，实例名称设为 `OpencodeClient`，参数结构采用扁平化设计以简化 API 调用。Fetch 插件使用原生 fetch 作为 HTTP 客户端基础，默认 baseUrl 指向本地开发服务器地址。

生成配置的关键参数包括：`exportFromIndex: false` 控制是否从 index 文件导出所有内容，`auth: false` 禁用自动认证处理以支持自定义认证逻辑，`paramsStructure: "flat"` 将嵌套参数展平为独立参数列表。这些配置共同决定了 SDK 的 API 风格和使用体验。

### 自定义 Fetch 实现

客户端默认使用无超时设置的 customFetch 实现，解决标准 fetch 在某些场景下的超时限制问题。实现通过 `@ts-ignore` 忽略类型检查，因为需要修改请求对象的 timeout 属性。customFetch 直接包装原生 fetch 调用，不设置任何超时限制，确保长时间运行的请求不会被中断。这种设计特别适合 AI 会话交互等可能需要较长响应时间的场景。

对于目录感知功能，客户端实现了智能编码处理。当 directory 参数包含非 ASCII 字符时，会自动使用 `encodeURIComponent` 进行编码，确保特殊字符能够正确传输。编码后的目录值通过 `x-opencode-directory` 请求头传递给服务器，实现多语言目录名的兼容支持。

### HTTP 客户端核心

生成的核心客户端实现基于拦截器模式，提供完整的请求响应生命周期管理。创建客户端时首先合并用户配置和默认配置，生成初始请求选项。请求拦截器链在发送请求前执行，支持认证参数设置、请求验证和参数修改。响应拦截器链在收到响应后执行，支持错误处理、响应转换和数据提取。

客户端支持多种序列化格式的自动处理，包括查询参数的序列化和 URL 路径参数的编码。安全参数处理支持多种认证方式，可根据 API 需求配置不同的认证机制。头信息合并确保用户自定义头和默认头正确组合，避免冲突和遗漏。

### 服务器实现架构

嵌入式服务器基于 Node.js 的 child_process 模块实现，使用 spawn 机制启动独立进程。服务器启动时会读取 OpenAPI 规范文档，启动本地 OpenCode 服务实例，并将服务 URL 返回给调用方。服务器配置支持完整的生命周期管理，包括启动参数、信号处理和超时控制。

服务器实现还提供 TUI 模式支持，通过 `TuiOptions` 配置可以在终端中运行交互式界面。这种模式适合本地开发和调试场景，提供可视化的交互体验。服务器返回的 URL 可直接用于客户端配置，实现客户端和服务器的无缝集成。

## 使用模式详解

### 基础客户端模式

最简单的使用模式是创建独立的客户端实例并调用 API 方法。这种模式适合与已有的 OpenCode 服务器集成，只需要配置服务器地址即可开始使用。客户端会自动处理请求序列化、响应解析和错误处理，开发者只需要关注业务逻辑即可。

基础模式的关键代码是调用 `createOpencodeClient` 函数并传入配置对象。配置对象可以包含 `baseUrl` 指定服务器地址，`headers` 添加自定义请求头，`fetch` 替换默认的 HTTP 客户端实现。配置对象的所有属性都是可选的，不提供配置时使用默认值。

### 嵌入式服务器模式

嵌入式服务器模式适合本地开发和测试场景，通过 `createOpencodeServer` 或 `createOpencode` 函数快速启动本地服务。这种模式的优势是开发者可以完全控制服务器生命周期，包括启动、停止、配置修改等操作。服务器启动后会返回服务 URL，客户端使用该 URL 建立连接。

嵌入式模式特别适合以下场景：单元测试中模拟完整的 API 环境、集成测试中提供可控的测试数据、本地开发中避免依赖外部服务的可用性。服务器默认配置为单用户模式，不适合生产环境使用。

### 批量处理模式

示例代码展示了 SDK 的批量处理能力，通过并发创建多个会话并同时执行任务。这种模式充分利用了异步并发的优势，显著提高批量操作的效率。实现方式是通过 `Promise.all` 等待所有任务完成，或者使用 `Array.fromAsync` 配合 for 循环逐个处理。

批量处理的关键技术点包括：会话的独立创建和管理，每个任务使用独立的会话避免状态干扰；文件路径的自动化处理，支持使用 glob 模式匹配多个文件；内容类型的多样化支持，可以同时发送文件内容和文本描述。

## 构建和发布流程

### 构建脚本功能

构建脚本执行完整的代码生成和编译流程，确保 SDK 的类型安全和代码质量。首先从主项目获取最新的 OpenAPI 规范文档，然后调用 `@hey-api/openapi-ts` 为 v2 版本生成代码。生成完成后使用 Prettier 格式化生成代码，最后运行 TypeScript 编译器进行类型检查。

构建脚本的自动化特性包括：自动拉取 OpenAPI 规范、自动清理旧的生成文件、自动格式化代码、自动执行类型检查。这些自动化步骤确保每次构建都是可重复的，并且符合项目的代码质量标准。

### 发布脚本流程

发布脚本负责将 SDK 包发布到 npm 仓库，支持多版本通道管理。发布前会修改 package.json 的 exports 配置，将 TypeScript 源文件路径转换为打包后的 JavaScript 和类型定义路径。发布完成后自动恢复原始的 package.json 配置，保持源码的整洁性。

发布脚本使用 `@opencode-ai/script` 提供的发布基础设施，支持版本标签管理和访问控制。发布命令通过 `bun pm pack` 创建安装包，然后使用 `npm publish` 发布到 npm 仓库。通道参数支持不同版本的发布策略，如 `latest`、`beta` 或 `next`。

## 高级特性

### 服务器发送事件支持

SDK 内置完整的 SSE（Server-Sent Events）支持，通过 `createSseClient` 实现实时事件流订阅。SSE 客户端基于生成的核心 SSE 模块构建，提供事件解析、连接管理和错误处理等完整功能。事件流接口支持异步迭代器模式，开发者可以使用 `for await...of` 语法便捷地处理事件数据。

SSE 功能的主要应用场景包括：实时接收 AI 会话的中间结果、监控系统状态变更、接收通知和警报消息。SSE 相比轮询具有更低的延迟和更少的服务器负载，是实现实时功能的推荐方案。

### 参数扁平化设计

v2 版本采用扁平化的参数结构设计，简化 API 调用的参数传递方式。传统的嵌套参数结构要求开发者了解完整的数据层次，扁平结构将所有参数都作为顶级属性传递，减少了代码的复杂度和出错可能性。这种设计参考了现代 SDK 的最佳实践，提供了更好的开发体验。

扁平化参数结构在实践中的优势包括：IDE 自动补全更准确，类型检查更严格，代码可读性更高。开发者可以直观地看到每个参数的用途，无需在嵌套结构中寻找目标参数。这种设计在保持类型安全的同时，提供了更简洁的 API 使用方式。

### 类型导出策略

SDK 采用按需导出的策略，避免一次性导出过多类型造成命名空间污染。导出配置在 package.json 的 `exports` 字段中定义，每个导出路径都有明确的用途和对应文件。开发者可以只导入需要的类型和函数，保持代码的精简和可维护性。

主要导出点包括：主入口 `index.ts` 导出完整的客户端和服务器功能；客户端入口 `client.ts` 导出纯客户端相关类型和函数；服务器入口 `server.ts` 导出纯服务器相关类型和函数；v2 入口 `v2/index.ts` 导出 v2 版本的完整功能。这种分层导出策略适合不同规模和复杂度的应用场景。

## 开发最佳实践

### 环境配置建议

使用 SDK 前需要确保开发环境满足以下要求：Bun 运行时 1.0 或更高版本、TypeScript 5.0 或更高版本、Node.js 18 或更高版本。推荐使用项目内置的依赖版本，通过 `catalog:` 引用确保团队成员使用一致的开发工具链。环境变量配置可以覆盖默认的服务器地址和超时设置。

### 类型安全使用指南

充分利用 SDK 提供的类型系统可以获得最佳的编码体验和错误预防效果。在调用 API 方法时，TypeScript 编译器会自动检查参数类型的正确性，拒绝不符合规范参数类型的调用。响应数据的类型在编译时已知，开发者可以安全地访问响应对象的属性而无需运行时检查。

类型安全的实践建议包括：始终使用接口定义的类型而非 any 类型；在处理响应数据时利用类型断言进行精确访问；启用 TypeScript 的严格模式获得更强的类型检查；在 IDE 中充分利用智能提示和导航功能。

### 错误处理策略

SDK 的错误处理遵循 Promise rejection 模式，API 调用失败时会抛出包含错误信息的异常。开发者需要使用 try-catch 或 Promise 的 catch 方法捕获和处理错误。常见的错误类型包括：网络连接错误、认证失败错误、参数验证错误和服务器内部错误。

错误处理的最佳实践包括：为不同的错误类型实现差异化的处理逻辑；提供用户友好的错误提示信息；记录错误日志便于问题排查；对于可恢复的错误实现重试机制；使用AbortSignal 支持请求的取消和超时控制。

## 性能优化建议

### 连接复用策略

SDK 客户端实例应该被复用而非每次请求都创建新的。创建客户端实例有一定开销，复用实例可以复用 HTTP 连接池、拦截器链和配置缓存。对于长期运行的应用程序，建议在应用启动时创建客户端实例并保持存活状态。

### 并发请求优化

充分利用异步并发能力可以显著提高批量操作的效率。SDK 的所有 API 调用都返回 Promise，支持 Promise.all 和 Promise.allSettled 进行并发控制。对于相互独立的请求，并发执行可以大幅减少总体执行时间。但需要注意服务器负载限制，避免发起过多并发请求。

### 大文件传输优化

处理大文件时应该使用流式传输而非一次性加载到内存。SDK 支持通过 URL 引用方式传递文件内容，避免大文件占用过多内存。对于需要上传大文件的场景，考虑实现进度跟踪和断点续传功能。

## 集成指南

### 与主流框架集成

SDK 可以无缝集成到各种前端和后端框架中。在 React 应用中使用 `createOpencodeClient` 创建客户端实例，通过 React Context 或状态管理库共享实例。在 Node.js 后端服务中使用 `createOpencodeServer` 启动嵌入式服务器或连接外部服务。在命令行工具中直接使用 SDK 功能构建自动化脚本。

### 与构建工具集成

SDK 的包格式支持主流 JavaScript 构建工具的集成。Webpack、Rollup、Vite 等工具都能正确识别 package.json 的 exports 配置。TypeScript 编译器能够正确解析类型定义和提供类型检查支持。对于使用 esbuild 的项目，需要额外配置类型解析。

### 测试策略建议

为使用 SDK 的代码编写测试时，可以选择以下策略：使用嵌入式服务器模式启动本地服务进行集成测试；使用 Mock 框架模拟客户端响应进行单元测试；使用录制回放技术捕获真实 API 响应进行回归测试。推荐建立完整的测试覆盖，包括正常流程和异常流程的测试用例。

## 版本管理和迁移

### 版本号规范

SDK 采用语义化版本号（Semantic Versioning），格式为 `主版本.次版本.修订版本`。主版本号变化表示存在不兼容的 API 变更；次版本号变化表示新增功能且保持向后兼容；修订版本号变化表示问题修复和小改进。当前版本 1.1.45 表示主版本 1、次版本 1、修订版本 45。

### 从 v1 迁移到 v2

v2 版本相比 v1 有以下改进：参数结构从嵌套变为扁平化，简化 API 调用方式；生成代码组织结构更清晰，模块划分更合理；新增更多便捷功能和优化实现。迁移时需要更新导入路径从 `gen` 到 `v2`，调整参数传递方式，测试所有 API 调用是否正常工作。v1 版本将继续维护以支持现有用户。

## 总结

`@opencode-ai/sdk` 是一个功能完整、设计精良的 TypeScript SDK，为 OpenCode 项目提供全方位的 API 访问能力。通过 OpenAPI 规范自动生成代码确保了 SDK 与 API 的严格同步，类型安全的设计提供了优秀的开发体验，双版本架构保证了向后兼容性。SDK 的嵌入式服务器功能特别适合本地开发和测试场景，批量处理能力和 SSE 支持满足了复杂应用场景的需求。通过遵循文档中的最佳实践和使用指南，开发者可以充分发挥 SDK 的潜力，构建高质量的 OpenCode 集成应用。
